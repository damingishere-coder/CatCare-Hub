# P12 安全与权限隔离执行任务（历史方案）

> 当前已改为本机免登录模式。本文只记录当时的实现要求，不再代表当前运行方式；现行方案见 [LOCAL_NO_AUTH.md](./LOCAL_NO_AUTH.md)。

## 背景

P0-P11 已完成本地管理后台、移动执行端、客户填写入口与 PWA。当前所有 `/api/admin/*` 与 `/api/mobile/*` 接口仍可匿名访问；客户填写令牌虽随机、可关闭、可过期且只能访问自身提交，但令牌原文仍存储在数据库中。正式开发文档要求 P12 建立 admin、mobile、fill 三类入口的权限边界，并为后续私网访问或仅公开 `/fill/*` 做准备。

## 目标

1. 为本地后台和移动执行端建立访问码登录、服务端会话、注销和角色隔离。
2. 保护全部管理与执行 API，保持健康检查和有效的客户填写入口匿名可用。
3. 将客户填写令牌改为哈希落库，同时保证迁移前已发出的原链接继续有效。
4. 完成登录限流、Cookie/Origin/缓存等基础 Web 安全控制，并补齐写入模型的输入拒绝策略。
5. 提供 Windows 首次配置和后续重置访问码的安全脚本；仓库不保存明文访问码或真实 `.env`。
6. 编写本地、Tailscale 私网和 Cloudflare Tunnel 路径隔离说明，但不实际开放公网。

## 允许修改范围

- `backend/app/`：认证、授权、会话、Token 哈希、安全响应头、输入校验及路由装配。
- `backend/migrations/`：P12 数据库迁移。
- `backend/scripts/`、`scripts/`：本地访问码初始化与 Windows 启动前检查。
- `backend/tests/`、`frontend/src/**/*.test.*`：P12 自动化测试及原测试的认证适配。
- `frontend/src/`：登录页、认证状态、路由守卫、注销入口和一次性填写链接交互。
- `.env.example`、`README.md`、`docs/`：配置模板、安全部署边界和本轮说明。

## 禁止修改范围

- 不改变 React + TypeScript + Vite + FastAPI + SQLAlchemy + SQLite/Alembic 技术栈。
- 不实现 OAuth、SSO、复杂用户管理、多租户 RBAC、任务分配或审计中心。
- 不执行 Cloudflare、Tailscale、服务器部署、Git push、生产数据库迁移或任何远程写入。
- 不读取、提交或回显真实 `.env`、客户资料、数据库、照片、Cookie、访问码或其他秘密。
- 不对 P0-P11 业务流程做无关重构，不提前进行 P14 重度 UI 设计。

## 已确定实现要求

### 身份与会话

- 两个固定本地角色：`admin` 与 `mobile`。访问码只以带随机 salt 的 PBKDF2-SHA256 哈希配置在本地 `.env`；代码库没有默认访问码和明文凭据。
- 登录成功生成至少 256 bit 随机 opaque Token；数据库仅保存 Token 的 SHA-256 哈希、角色和过期时间。
- 会话 Cookie 必须 `HttpOnly`、`SameSite=Strict`、路径 `/`，支持配置 HTTPS 下的 `Secure`；注销删除服务端会话并清 Cookie。
- `admin` 可访问 `/api/admin/*` 和 `/api/mobile/*`；`mobile` 只能访问 `/api/mobile/*`；`/api/fill/*` 不因已登录而获得任何后台权限。
- `/api/auth/session` 只返回当前角色与过期时间，不返回任何 Token、哈希或访问码。

### Web 安全边界

- 所有 admin/mobile API 默认无会话返回 401、角色不匹配返回 403，不能依赖前端路由守卫代替后端授权。
- 对使用会话 Cookie 的非安全方法校验同源 `Origin`；本机与显式配置的可信 Origin 可通过。登录同样执行 Origin 校验。
- 登录按客户端地址和角色做单进程限流，错误响应不区分“未配置”和“访问码错误”之外的账户细节；未配置访问码时返回明确的本地配置错误。
- 敏感 API 返回 `Cache-Control: no-store`、`Pragma: no-cache`、`X-Content-Type-Options: nosniff`、合理的 Referrer Policy；不引入会破坏高德地图的激进 CSP。
- 不信任 `X-Forwarded-For`；反向代理场景在文档中要求由受控代理限制来源。

### 客户填写 Token

- 迁移新增唯一 `token_hash`，用 SHA-256 回填现有 Token 原文，然后删除明文 Token 列；原客户 URL 仍可通过相同原文计算哈希后查询。
- 新建 Token 时仅在该次响应返回 `fill_path`；后续列表和状态修改不再恢复原文，`fill_path` 为 `null`。
- 前端只在新建后展示和复制一次链接，并明确丢失后需生成新链接；日志、错误和数据库均不回显原文。
- 继续保留格式、状态、过期、单次提交和跨 Token 隔离检查；公共 fill 响应禁止缓存并使用 `no-referrer`。

### 初始化、输入与现有功能

- Windows `setup.ps1` 在依赖就绪后调用本地初始化脚本：缺失时生成独立 admin/mobile 访问码，原文只打印一次，`.env` 仅写入哈希；已有值不覆盖。
- 提供显式本地重置命令，避免将访问码放在命令行参数或 Git 文件中。
- 启动脚本在认证哈希缺失时拒绝启动并提示先运行 setup，不能以不安全默认值回退。
- 所有写入型 Pydantic 模型拒绝未声明字段；现有图片格式、MIME、大小、像素、随机路径与归属校验继续生效，且上传/下载先经过角色授权。
- 前端提供 `/login`，保护 `/admin/*` 与 `/mobile/*` 深链；保留 `/fill/:token` 完全独立。401 回到登录，403 提供清晰的角色提示；不把会话放入 localStorage。

## 验收标准

1. 数据库可从 0004 升级到 P12 head，旧 Token URL 在升级后仍可使用，数据库不再保存 Token 原文。
2. health 与有效 fill 匿名可用；所有 admin/mobile 端点未登录均被拒绝。
3. admin/mobile 角色矩阵、会话过期、注销、错误访问码、Origin 校验和限流均有自动化证据。
4. Cookie 属性满足要求，响应不泄漏访问码、会话 Token、客户填写 Token 或密码哈希。
5. 新填写链接只在创建响应出现一次；刷新列表后不可重建原链接，关闭/恢复/过期逻辑不退化。
6. 前端登录、深链守卫、角色跳转、退出和一次性链接交互有测试覆盖；`/fill/:token` 无需登录。
7. 原 P0-P11 测试通过，前端 lint、typecheck、test、build 和后端全量测试通过。
8. Windows 脚本可在隔离临时 `.env`/数据库上验证幂等初始化；默认业务数据库与真实 `.env` 不作为测试目标。
9. Git diff 中没有真实数据、秘密、数据库、上传、日志、临时文件、调试代码或范围外改动。

```powershell

npm test --prefix frontend -- --run
npm run lint --prefix frontend
npm run typecheck --prefix frontend
npm run build --prefix frontend
.\.venv\Scripts\python.exe -m compileall -q backend\app backend\migrations backend\scripts
git diff --check
git status --short
git diff --stat
```

对迁移、认证初始化和端到端启动检查必须设置独立的 `CATCARE_DATABASE_URL` 与临时 env 路径，不能访问或覆盖默认 `data/catcare.db` 和真实 `.env`。

## 返回格式

Operator 只返回：

1. `summary`：成功或失败，以及是否修改任何源文件。
2. `commands`：逐条命令、退出码、测试数量和关键输出。
3. `security_matrix`：匿名/admin/mobile/fill 的访问结果、Cookie/Origin/限流/Token 哈希证据。
4. `privacy_scope`：数据库、上传、`.env`、日志、依赖和 Git 范围检查结果。
5. `warnings`：失败重试、环境差异或剩余风险。
6. `verdict`：仅陈述验证事实，不代替主代理最终验收。
