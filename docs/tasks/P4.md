# P4｜订单计划与按天排程执行任务

## 背景

P0–P3 已建立 Windows 本地后台、数据库与迁移、客户/多猫档案，以及订单创建、后端计费和多日任务自动生成闭环。正式开发文档要求 P4 将 `/admin/plans` 升级为项目核心调度页面，采用“左侧按天计划、中间路线地图、右侧任务详情”布局，并完成日期切换、每日任务、人工排序、保存排序、任务详情和状态修改。

现有 `Task.service_date`、`planned_time`、`sort_order`、`status` 和关联模型足以覆盖本轮，不需要新增数据库字段。真实地图、地理编码、距离/时间和推荐路线明确属于 P5。

## 目标

1. 建立按日期汇总、读取当日任务和读取单个任务详情的后台 API。
2. 支持给当日全部任务设置可空计划时间，并用上移/下移人工调整顺序后原子保存。
3. 使用日计划修订值进行乐观并发校验，避免旧页面覆盖新任务或另一窗口的排程。
4. 建立不破坏执行历史的排程锁定规则和计划状态修改边界。
5. 将 `/admin/plans` 默认升级为三栏调度页，同时保留同一入口下的 P3 订单管理能力。
6. 为 P5 保留明确的地图工作区，但不伪造真实地图、距离、预计路程或自动路线。

## 允许修改范围

- `backend/app/api/plans.py`：P4 按天计划、任务详情、排程和状态 API。
- `backend/app/schemas/plan.py`：P4 请求/响应模型。
- `backend/app/services/plans.py`：日期任务读取、修订值、排程校验和计划状态规则。
- `backend/app/services/orders.py`：提取可复用的单任务执行历史判断。
- `backend/app/main.py`：挂载计划 Router。
- `backend/tests/`：P4 服务与 API 自动测试。
- `frontend/src/features/plans/`：计划 API、类型、三栏页面与视图切换。
- `frontend/src/features/orders/OrdersPage.tsx` 及其测试：移除已经过时的 P4 占位说明并适配组合入口。
- `frontend/src/routes/`：接入 P4 页面并保留 `/admin/orders` 兼容入口。
- `README.md`、`DEVELOPMENT_PROGRESS.md` 和本任务文件。

## 禁止修改范围

- 不新增左侧一级导航；订单管理和执行计划继续合并在“订单计划”。
- 不接入高德、百度、腾讯或其他地图 SDK/API，不调用外部地理编码服务。
- 不实现 Marker、真实路线、距离、行驶时间、推荐顺序、一键采用或复杂路径算法；这些属于 P5。
- 不实现拖拽排序；本轮使用明确可访问的上移/下移按钮。
- 不实现 P6 的执行 Checklist、开始/完成服务、照片上传、现场备注或异常处理。
- 不实现 P7 工作台统计、P8 收款流水、P9 手机执行端、P10 客户填写、P11 PWA、P12 完整鉴权或 P14 重度 UI 重构。
- 不删除或重建任务、任务事项、照片和执行记录。
- 日计划列表不得批量返回手机号、完整地址、门禁、钥匙或客户备注。
- 右侧单任务详情只返回本轮明确需要的完整地址、订单/任务备注和猫咪服务/用药注意事项；不返回手机号、微信、门禁、钥匙或客户备注。
- 不提交真实客户/订单资料、数据库、上传照片、`.env`、日志或 `.runtime` 数据。

## 已确定实现要求

### 日期与汇总

- 日期采用业务本地日期 `YYYY-MM-DD`，不从 UTC 时间戳推导服务日。
- 日期汇总返回所有存在任务的服务日，按日期升序。
- 每日“订单数”按去重 `order_id` 统计；“猫咪数”按当天订单关联的去重 `cat_id` 统计，避免同一订单每天多次服务重复计数。
- 空日期读取返回 `200` 和空任务列表；具体任务不存在返回 `404`。
- 前端默认优先选择今天；今天无任务时选择最近的未来服务日；没有未来任务时选择最近的历史服务日；完全无任务时仍显示今天的空计划。

### 当日任务与隐私

- 当日任务按 `sort_order`、任务 ID 稳定排序。
- 列表任务只返回任务/订单 ID、日期、计划时间、顺序、状态、客户 ID/姓名/小区、猫咪 ID/姓名和服务事项摘要。
- 列表不得返回手机号、地址、门禁、钥匙、客户备注、照片路径或其他客户详情。
- 选中单个任务后，右侧详情返回客户姓名、小区、地址、楼栋、单元、房号，关联猫咪服务/用药注意事项、订单备注、任务备注、计划时间、已有预计到达值、任务事项完成状态和照片数量。
- 详情不返回手机号、微信、门禁、钥匙、客户备注或照片路径。

### 排序、时间与并发

- `planned_time` 接受 `HH:MM[:SS]` 或 `null`；时间可空，不强制按时间递增。
- 当天路线顺序由 `sort_order` 权威决定，计划时间只用于展示和人工录入，不隐式重排。
- 保存排程请求必须包含当天全部任务且每个任务恰好一次；数组顺序即最终路线顺序。
- 服务端只接收任务 ID 和计划时间，统一写入连续 `sort_order = 0..n-1`；拒绝重复、遗漏和跨日期任务。
- 当日任务、状态、时间、执行标记、事项完成和照片 ID 共同生成不含敏感数据的 SHA-256 修订值；保存排程和状态修改都必须提交当前修订值。
- 修订值过期、当天任务集合变化或请求混入跨日任务时返回 `409`，不得部分写入。
- 若当天任一任务处于 `in_progress/completed/exception`，或已有开始/完成时间、照片、已完成事项，则整个当日排程锁定，计划时间和排序不可再改，避免篡改执行历史。
- 排程保存只更新 `planned_time` 和 `sort_order`，不删除、不重建任务或事项。

### 计划状态

- P4 只允许把没有执行历史的任务改为 `pending`、`confirmed`、`ready`、`cancelled`。
- `in_progress`、`completed`、`exception` 由 P6 的执行流程负责；P4 请求这些目标状态返回 `409`。
- 已有执行历史的任务不可通过 P4 改回计划状态。
- 订单已取消或已完成时，任务状态由订单流程管理，P4 单任务状态接口返回 `409`。
- P4 单任务计划状态修改不反向改写订单状态；订单状态继续由 P3 订单流程维护。

### 页面与路由

- `/admin/plans` 默认显示“按天计划”；同一页面提供“订单管理”切换，继续使用 P3 的 `OrdersPage`。
- `/admin/orders` 重定向到 `/admin/plans?view=orders`，保留直接进入订单管理的兼容语义。
- 左栏显示日期汇总、日期跳转、当天任务、计划时间、客户、小区、猫咪数量、状态、上移/下移和保存排程。
- 中栏保留“路线地图”工作区，用编号顺序预览展示当天未取消任务；明确标注真实地图、坐标、距离和预计路程将在 P5 接入，不展示伪造数值。
- 右栏显示选中任务详情和允许的计划状态操作；无任务或未选中时提供清晰空状态。
- 有未保存排程时禁止切换日期、切换到订单管理或修改任务状态；用户可保存或撤销，避免静默丢失。
- 执行历史锁定时禁用时间和排序控件，并显示原因。

## 验收标准

1. 两笔订单在同一天生成任务后，日期汇总正确返回去重订单数、任务数和猫咪数。
2. 选择某一天只读取当天任务，空日期返回空列表，任务列表不包含客户敏感字段。
3. 三个当天任务可通过上移/下移调整顺序、设置或清除计划时间，保存后数据库顺序为连续 `0,1,2`，刷新后保持。
4. 重复、遗漏、跨日任务或旧修订值保存返回 `422/409`，数据库不发生部分更新。
5. 当天存在执行历史时排程保存返回 `409`，原时间、顺序、事项和照片不变。
6. 任务详情只在选中单项后返回完整地址和服务注意事项，不返回手机号、微信、门禁、钥匙、客户备注或照片路径。
7. 无执行历史任务可以在四种计划状态之间修改；P4 直接设置执行状态、修改已执行任务、修改取消/完成订单任务均返回 `409`。
8. `/admin/plans` 默认为三栏计划页，日期切换、排序、保存、撤销、详情和状态操作可用；订单管理仍可在同一入口使用。
9. 中栏只展示路线顺序工作区和 P5 边界说明，不调用外部地图或生成虚假距离/用时。
10. Windows 临时数据库通过 Vite 代理完成日期查询、三任务排序/时间保存、刷新持久化、修订冲突、详情隐私和计划状态修改；启停后端口正确释放。
11. P0–P3 的订单、客户、迁移、Seed、路由和构建回归保持通过。

1. P4 日期汇总、日计划、排序/时间、修订值、状态和隐私边界摘要。
