# P1｜数据库与核心业务模型执行任务

## 背景

P0 已建立 React 前端、FastAPI 后端、三端路由、Windows 启停和安全忽略规则。后端当前只有健康检查，没有数据库、ORM、迁移或业务接口。正式开发文档要求 P1 建立核心实体、迁移机制和测试数据 Seed，并能通过数据库正常创建客户、猫咪、订单、任务和收款。

## 目标

1. 使用 SQLAlchemy 2 建立 SQLite 本地数据库层，并保持未来 PostgreSQL 迁移兼容性。
2. 使用 Alembic 建立可升级、可降级的迁移机制和首个完整迁移。
3. 建立客户、猫咪、订单、订单猫咪关联、任务、任务事项、任务照片、收款、客户填写 Token、客户填写提交共十张业务表。
4. 提供只包含明显虚构信息、可重复执行且不会重复插入的开发 Seed。
5. 提供 Windows 数据库迁移与 Seed 入口，并让首次 `setup.bat` 自动完成本地数据库迁移。
6. 通过自动测试验证迁移、外键、约束、关系、核心实体创建和 Seed 幂等性。

## 允许修改范围

- `backend/app/db/`：数据库配置、Base、引擎、会话和 Seed。
- `backend/app/models/`：P1 核心业务模型与枚举。
- `backend/migrations/`、`backend/alembic.ini`：迁移环境与版本文件。
- `backend/tests/`：迁移、模型、约束和 Seed 测试。
- `backend/requirements*.txt`：SQLAlchemy、Alembic 及测试所需依赖。
- `scripts/` 与根目录批处理：Windows 迁移、Seed 和 setup 集成。
- `.gitignore`、`README.md`、`DEVELOPMENT_PROGRESS.md` 和本任务文件。

## 禁止修改范围

- 不实现 P2 客户/猫咪页面或 CRUD API。
- 不实现 P3 订单创建、费用计算或自动生成任务业务逻辑。
- 不实现 P4 排程、P5 地图、P6 图片上传/任务执行、P8 收款页面或 P10 客户填写接口。
- 不实现完整鉴权、Token 授权或公网访问。
- 不把业务逻辑写死在 SQLite 特有能力上，不使用数据库 BLOB 保存图片。
- 不提交 SQLite 数据库、WAL/SHM 文件、真实客户数据、手机号、地址、门禁、钥匙、照片、`.env` 或运行时文件。

## 已确定实现要求

- 默认数据库位于仓库根目录被忽略的 `data/catcare.db`，可通过 `CATCARE_DATABASE_URL` 覆盖。
- 使用 SQLAlchemy 2 声明式模型、`Mapped` 类型和显式关系；SQLite 连接必须启用外键约束。
- 使用可移植的 `Numeric` 保存金额和坐标，使用 SQLAlchemy 通用 `JSON` 保存服务事项与客户提交 payload。
- 状态和类型使用非原生枚举约束，避免绑定 PostgreSQL 专有枚举。
- 迁移是建表的权威机制；应用启动不得使用 `Base.metadata.create_all()` 偷代迁移。
- 初始迁移包含正式文档 P1 列出的九张表，并纳入数据模型章节要求的 `task_photos`。
- `customers` 同时预留地图章节要求的 `latitude`、`longitude`、`geocode_status`。
- `cats` 预留 P2 所需的 `is_active`，订单保存可移植 JSON 服务事项。
- 所有时间戳、外键、唯一约束、金额非负、日期范围、每日次数和任务顺序等关键规则必须在数据库层表达。
- Seed 使用“演示客户（虚构）”“演示猫咪”等明显虚构内容，不包含真实手机号、真实地址、门禁、钥匙、照片或有效填写 Token。
- Seed 必须幂等；重复执行后核心表记录数量不增加。
- `setup.bat` 安装依赖后执行 `alembic upgrade head`；另提供 `migrate.bat` 和 `seed.bat`。

## 验收标准

1. 首次迁移可在空 SQLite 文件上创建十张业务表和 `alembic_version`。
2. 迁移可降级到空数据库，再重新升级到最新版本。
3. 能在数据库中持久化并关联客户、多只猫咪、订单、任务、任务事项、任务照片、收款、填写 Token 和提交。
4. SQLite 外键约束真实生效，关键检查约束能拒绝非法数据。
5. Seed 能创建客户、猫咪、订单、任务和收款，重复运行不重复写入。
6. 默认生成的数据库和所有临时数据库均不会进入 Git。
7. Windows 迁移与 Seed 脚本可从带空格的项目路径运行。
8. P0 前端测试、构建、后端健康检查和 Windows 启停仍保持通过。

## 测试命令

```powershell
# 安装/更新后端依赖
.\.venv\Scripts\python.exe -m pip install --disable-pip-version-check -r backend\requirements-dev.txt

# P1 后端自动测试
.\.venv\Scripts\python.exe -m pytest backend\tests

# 默认本地数据库迁移与 Seed（生成内容必须被 Git 忽略）
.\migrate.bat
.\seed.bat
.\.venv\Scripts\python.exe -m alembic -c backend\alembic.ini current

# P0 前端回归
npm run lint --prefix frontend
npm run typecheck --prefix frontend
npm test --prefix frontend -- --run
npm run build --prefix frontend

# Windows 启停回归
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -NoBrowser
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop.ps1

# Git 与敏感数据检查
git status --short
git diff --check
git diff --stat
```
