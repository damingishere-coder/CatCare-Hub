# P0｜项目检查与基础骨架执行任务

## 背景

正式 GitHub 仓库为 `https://github.com/damingishere-coder/CatCare-Hub.git`。仓库在 P0 开始前为空，没有提交、技术栈、前后端目录、数据库、页面或启动方式。项目正式开发依据为根目录《猫咪喂养登记系统-开发执行文档.md》，当前按 P0 → P14 顺序推进。

## 目标

1. 记录修改前的仓库基线到 `CURRENT_STATE.md`。
2. 采用文档为空项目推荐的 React + TypeScript + Vite 与 FastAPI 建立最小可运行骨架。
3. 建立 `/admin`、`/mobile`、`/fill` 路由边界，并预留 `/fill/:token`。
4. 在后台建立“工作台、订单计划、客户档案、收款记录、设置”五项左侧导航。
5. 从第一轮建立完善的敏感数据和运行时数据忽略规则。
6. 提供适用于 Windows 的安装、启动、停止入口。

## 允许修改范围

- 仓库根目录的说明、Git 配置、依赖锁文件和 Windows 启停脚本。
- `frontend/`：P0 页面骨架、路由、布局、样式及其自动测试。
- `backend/`：最小 FastAPI 应用、健康检查及其自动测试。
- `scripts/`：仅限 Windows 本地安装、启动、停止所需脚本。
- `docs/`：P0 任务文件和开发进度记录。

## 禁止修改范围

- 不实现 P1 的数据库、ORM、迁移、Seed 或业务实体。
- 不实现 P2–P10 的客户、猫咪、订单、任务、地图、收款、执行或客户提交业务逻辑。
- 不实现 P11 的完整 PWA 能力，不实现 P12 的完整权限系统，不提前执行 P14 UI 重构。
- 不开放公网，不部署，不接入真实地图服务，不写入任何真实客户数据。
- 不提交数据库、照片、上传文件、`.env`、日志、缓存、虚拟环境或其他运行时数据。

## 已确定实现要求

- 前端使用 React、TypeScript、Vite、React Router、Tailwind CSS 和 Lucide Icons。
- 后端使用 FastAPI；P0 只提供 `/api/health` 健康检查。
- `/` 重定向到 `/admin`；未知路由显示明确的 404 页面。
- `/admin` 使用共享布局；五项导航分别对应可独立访问的后台路由。
- `/mobile` 明确标注为后续轻量执行端；`/fill` 与 `/fill/:token` 明确标注为预留客户填写端。
- 前端开发服务器和后端均支持监听 `0.0.0.0`，默认仍仅作本地使用；前端默认端口为 `5180`，避免与本机已有开发服务冲突。
- 提供 `setup.bat`、`start.bat`、`stop.bat`；运行状态和日志只写入被忽略的 `.runtime/`。
- 所有路径处理兼容 Windows，错误场景给出可理解提示。

## 验收标准

1. `CURRENT_STATE.md` 准确记录空仓库基线。
2. `.gitignore` 覆盖敏感数据、数据库、上传、环境变量、依赖、构建、缓存、日志和运行状态。
3. 前端依赖可安装，类型检查、自动测试和生产构建通过。
4. 后端依赖可安装，自动测试通过，`/api/health` 返回成功状态。
5. `/admin`、五个后台页面、`/mobile`、`/fill`、`/fill/:token` 均能正确渲染。
6. 后台五项导航可见，当前页面状态清晰。
7. Windows 脚本能够完成安装、启动和停止，不依赖项目外路径。
8. Git 差异中不含真实业务数据、密钥、数据库、上传、日志或临时文件。

## 测试命令

```powershell
# 前端
npm ci --prefix frontend
npm run lint --prefix frontend
npm run typecheck --prefix frontend
npm test --prefix frontend -- --run
npm run build --prefix frontend

# 后端（先由 setup.bat 建立 .venv）
.\.venv\Scripts\python.exe -m pytest backend\tests

# Windows 一键入口冒烟验证
.\setup.bat
.\start.bat
.\stop.bat

# Git 范围检查
git status --short
git diff --stat
```

3. Git 差异与敏感数据检查结论。
