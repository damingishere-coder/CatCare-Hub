# P24｜客户填写页精简与设计升级

## 背景

群晖公网填写链路已经打通，但当前客户页面字段平铺、可选信息过多、手机端层级不清晰。本轮把它收敛为“核心登记 + 折叠选填”，同时保留既有 Token、不可变原稿、后台审核、幂等提交和 30 天清理边界。

## 目标

- 客户最低只需填写称呼，以及微信或手机号之一。
- 默认展示联系方式、可选日期和每日次数；地址交接、猫咪资料按需展开。
- 删除公开页上的草稿按钮、猫砂和用药字段，合并公开备注。
- 后台审核稿可以把客户填写备注复制到客户长期备注或本次订单备注。
- NAS 只更新公开 Relay 和 Gateway，不迁移或重启 PostgreSQL。

## 允许修改

- `frontend/src/pages/FillPage.tsx` 及对应测试。
- `frontend/src/features/intake/AdminIntakePage.tsx` 及对应测试。
- 为本轮行为所必需的 intake 前端类型、常量和测试。
- `deploy/synology/**` 中的 Relay/Gateway 构建、受限 SSH 和部署说明。
- 本任务文档。

## 禁止修改

- `.env`、密码、Token、Cookie、证书和 NAS 凭据。
- SQLite/PostgreSQL 数据结构、Token 哈希、提交锁定、幂等和清理策略。
- 本地管理后台、DSM、SSH、SMB、PostgreSQL 的公网边界。
- `README.md`、`README.en.md`、`LICENSE`、`.github/**`、`docs/assets/**` 及当前主页装修文件。
- 不执行 reset、stash、clean，不提交或推送。

## 已确定实现

- 公开页始终单列，温暖简洁猫咪风；底部固定提交栏适配安全区域。
- 称呼必填；手机或微信至少一项。日期可选且允许只填一个。
- 每日次数使用“每天 1 次 / 每天 2 次 / 待确认”。
- 地址与交接默认折叠，保留完整地址、门禁方式、钥匙状态；后两项只允许固定选择，不收实际密码、钥匙编号或进门步骤。
- 猫咪资料默认折叠且可选；每只猫只显示名字、饮食、特殊注意事项。
- 删除公开页保存草稿操作；旧草稿和原有 API 仍兼容，隐藏的旧字段不丢失。
- 公开备注合并为待审核备注；后台提供复制到客户长期备注或本次订单备注的操作。
- 提交前二次确认，留存说明压缩为两行，成功页说明后续通过微信或电话联系。
- 新生成链接使用 `/f/` 短路径和 128 位随机码；旧 `/fill/` 链接继续有效，Token 仍只存哈希。
- 受限 SSH 增加固定、无参数的公网更新命令；只重建 Relay/Gateway，使用固定路径、SHA-256 校验、健康检查和失败自动回滚，并修正 `catcare health` 地址。

## 验收标准

- 390×844、430×932 无横向溢出、字段错位或固定栏遮挡。
- 联系方式、折叠区、次数选择、旧草稿兼容、提交确认和终态均有测试。
- 前端测试、类型检查、公开构建通过。
- 公网更新前另行确认；更新后 HTTPS、提交锁定和公网隔离均通过。
- 受限 SSH 继续拒绝任意命令，Gateway 更新失败可回滚。
