# P21：闭环路线规划、坐标可信度与高德稳定性

## 背景

路线页日期导航只显示日期和数量；历史错误坐标仍被当作已解析坐标使用，导致地图视野被拉到全国且高德电动车路线返回 `RESULTS_ARE_EMPTY / 30007`。现有顺序建议仅为经纬度最近邻，界面又默认展示原顺序道路路线，无法形成清晰、稳定的多点规划体验。

## 目标

- 日期导航直接显示客户名称。
- 旧坐标必须经过查询指纹与行政区校验后才能进入路线。
- 路线固定为“家 → 当天任务 → 家”，计划时间只约束先后顺序。
- 使用本地全局优化确定任务顺序，高德只计算优化后的电动车道路路线。
- 高德失败时保留可解释的本地顺序建议，不伪造道路里程或耗时。

## 允许修改范围

- `backend/app/maps`、路线/订单定位服务、计划 API 与 Schema。
- Customer、Order 地理编码可信度字段及一项 Alembic 迁移。
- `frontend/src/features/plans` 的接口类型、日期导航、地图和规划结果交互。
- 相关后端/前端测试、非敏感说明文档和本任务文件。
- 为验收而备份并迁移本机 CatCare SQLite；只按当前路线操作触发按需重新定位。

## 禁止修改范围

- 不读取、输出、修改或提交 `.env`、API Key、Token、Cookie、浏览器数据。
- 不批量联网重算历史订单坐标，不改写历史地址文本。
- 不修改已存在执行记录的历史任务坐标。
- 不引入 OR-Tools、VROOM、OSRM 或新的常驻服务与运行依赖。
- 不修改 OpenAI Provider、登录、认证或模型配置。
- 不覆盖、清理、暂存 `.codemap/`、`PROJECT_AUDIT.md` 或其他任务外文件。
- 不由子代理修改生产代码、执行 Git 提交/推送、部署或数据库迁移。

## 已确定实现要求

1. `PlanDaySummary` 返回按当天任务首次出现顺序去重的 `customer_names`；日期卡展示前两位，超出显示“另 N 位”。
2. Customer 与 Order 增加地理编码查询指纹、行政区编码和匹配级别。指纹基于 Provider、规则版本和隐私过滤后的规范化地址哈希，不保存额外地址副本。
3. 缺少指纹或指纹与当前查询不符的旧坐标为 `stale_geocode`，不得用于地图、导航或路线；迁移不删除原坐标，也不联网回填。
4. 高德地理编码返回坐标及 `city/district/adcode/level`；结果必须匹配查询中显式或默认补全的城市/行政区，否则标记 `geocode_mismatch` 且不使用该坐标。
5. 重新定位只更新订单、可安全同步的客户缓存和尚无执行历史的任务坐标；历史执行任务保持不变。
6. 本地路线固定回家。12 个及以下任务使用确定性的精确动态规划；更多任务使用确定性多起点最近邻加 2-opt。
7. 有计划时间的任务按时间先后形成约束；同一时间按当前顺序。未定时任务可插入任意不破坏约束的位置。不计算停留时长或承诺 ETA。
8. 高德只计算优化顺序的 `N + 1` 个电动车路段，路段并发上限 2，总预算 40 秒；成功路段仅在内存缓存 15 分钟、最多 512 条。
9. 网络超时、HTTP 502/503/504、高德 `10016/10020` 最多额外重试两次；Key、权限、配额、频率限制与 `30007` 不自动重试。
10. 高德道路计算失败时路线预览仍返回本地优化摘要，`road_route.status=degraded` 且真实道路指标为空；地址不完整时禁止采用建议。
11. 路线页移除“当前/推荐”双视图，默认显示规划结果、闭环链路、空间估算改善和真实电动车指标；按钮为“规划当天路线”。
12. 地图固定高度，只对已验证坐标执行 fit view；桌面标点显示序号与客户名。

## 验收标准

- 当前 `长坑三巷21号` 旧坐标不会进入地图；按需重定位后落在深圳龙岗并可生成回家闭环路线。
- 4 点反例证明新算法优于最近邻；闭环、时间先后、平局和大于 12 点路径均确定且可复现。
- 规划只调用优化路线的 `N + 1` 个道路段；瞬时错误重试，永久错误不重试；降级不显示假道路指标。
- 日期导航、地图标点、闭环链路、采用顺序、错误提示和窄屏布局均有前端测试。
- Alembic 升级/降级、数据库完整性、后端全量测试、前端测试、lint、类型检查和构建全部通过。
- 实际浏览器中地图保持深圳局部视野，客户名称可见，路线首尾均为家。
