# P17 启动与运行时稳定性修复

## 背景

2026-08-23 实机启动后，前端仍可能只显示应用壳，工作台出现 `Failed to fetch`，路线图长期停留在加载状态。现场同时存在 Alter 管理的 `0.0.0.0:8000/5180` 进程和 `start.bat` 自有的 `127.0.0.1:8000/5180` 启动逻辑；Windows 用户代理已启用，而项目部分入口仍使用 `localhost`。此外，现有 `/api/health` 不验证数据库迁移版本，前端请求没有统一超时和网络错误处理。

## 目标

- Alter 为当前电脑的主要运行器，`start.bat` 作为安全、幂等的备用入口。
- 前后端只监听 `127.0.0.1`，5180 与 8000 各最多一套 CatCare-Hub 服务。
- 启动在 15 秒内确认前端和业务 API 就绪；数据库版本不兼容时不得打开伪正常页面。
- 网络断开或服务切换时显示中文恢复提示并允许重试，不出现原始 `Failed to fetch` 或无限加载。

## 允许修改范围

- `backend/app`、`backend/tests`：新增业务就绪检查及测试。
- `scripts`、`start.bat`、`README.md`、相关本地访问文档：安全迁移前置、端口归属和统一入口。
- `frontend/src`：共享请求层、错误恢复组件、路线图加载状态和根错误边界。
- `.runtime/alter.catcare.json` 及本机 Alter 中仅属于项目 `245058ff-c15e-4398-b5ec-d3f10b8bbb37` 的两个进程定义；该运行文件保持忽略，不进入 Git。

## 禁止修改范围

- 不读取、输出、复制或提交 `.env` 中的 Key、Token 或其他秘密。
- 不修改业务表结构，不新增 Alembic 迁移，不改写客户、订单、任务或收款数据。
- 不停止、删除或重配任何其他 Alter 项目。
- 不修改 Windows 全局代理、防火墙或系统安全设置。
- 不强制推送、不重写 Git 历史，不提交数据库、日志、运行状态、构建产物或备份。

## 已确定实现要求

1. 保留 `/api/health` 兼容接口，新增 `/api/ready`；只有数据库可连接且 Alembic revision 等于唯一 head 时返回 200，否则返回去敏 503。
2. 启动前先判断当前数据库 revision。默认 SQLite 落后时，使用 SQLite backup API 在 `data/backups/` 创建一致性备份后再升级；非 SQLite 落后时停止并要求人工迁移。
3. `start.bat` 若发现两个端口均由本项目健康实例占用，应直接复用并打开 `http://127.0.0.1:5180/admin`；部分占用、错误服务或未知端口所有者必须失败并给出中文诊断，不能自动终止未知进程。
4. 前端统一 JSON 请求、HTTP 错误解析、Abort 超时与网络错误翻译。本地请求默认 15 秒，路线预览 45 秒，上传 60 秒。
5. 工作台和路线图必须提供可操作的重试；路线配置尚未成功读取时显示“状态未知”。根级渲染异常由错误边界接管。
6. Alter 两个进程定义改为 `127.0.0.1`；后端健康检查改为 `/api/ready`。替换前备份 Alter 元数据与状态，重置 CatCare 重启计数，并保留项目 ID 与 `web_port=5180`。

## 验收标准

- 后端全量 pytest、前端 lint/typecheck/test/build 全部通过。
- 隔离 SQLite 覆盖 ready、落后 revision、数据库不可达、备份与升级失败边界；不得拿正式业务库制造旧版本。
- Alter 启动后 8000/5180 仅有一套 `127.0.0.1` 监听；六个后台页面及关键代理 API 正常，浏览器无 warning/error。
- Alter 已运行时执行 `start.bat` 不产生重复进程；Alter 停止后 `start.bat` 可独立启动，`stop.bat` 只停止自己的进程。
- 后端断开后，前端在超时内显示中文恢复提示，恢复后重试成功。
- `git diff --check` 通过，暂存区不含秘密、业务数据、运行文件或范围外修改。
