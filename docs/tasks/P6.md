# P6｜任务执行任务文件

## 背景

P0-P5 已建立 Windows 本地 Web 骨架、数据库模型、客户档案、订单任务生成、按天排程和地图路线。正式开发依据《猫咪喂养登记系统-开发执行文档.md》第 9、10、17、22 节及 P6 轮次要求开发 `/admin/tasks/:id`，完成单次上门服务的开始、Checklist、照片、备注、猫咪状态、异常和完成闭环，并同步任务状态与订单进度。

当前 `Task` 已有状态、开始/结束时间和备注，`TaskItem`、`TaskPhoto` 也已建表；但没有执行 API/页面，也缺少猫咪状态和异常说明的独立字段。P7 工作台将直接消费本轮形成的权威任务/订单状态，本轮不提前实现其页面。

## 目标

- 建立后台单任务执行详情、任务级乐观并发 revision 和明确状态机。
- 支持开始任务、逐项 Checklist、保存本次备注与猫咪状态、上传本地照片、完成服务和标记异常。
- 自动同步订单进度，并保护已完成、异常或取消的执行历史。
- 在 Windows 本地环境安全保存图片，数据库只保存相对访问路径，Git 不接触任何运行时图片或真实业务数据。
- 从 P5 按天计划页进入任务执行页，并在操作后正确展示最新状态、时间、图片与校验提示。

## 已确定实现要求

### 数据与状态机

- 在 `tasks` 增加可空 `cat_status` 与 `exception_notes` Text 字段；`notes` 作为“本次执行备注”。迁移需支持 SQLite，并保持 PostgreSQL 兼容。
- 任务级 revision 必须至少覆盖：任务状态、开始/结束时间、执行文本、订单状态、Checklist 与照片记录；所有 P6 写操作携带 `expected_revision`，过期返回 `409` 且不产生部分更新。
- 仅 `confirmed`、`ready` 可开始；开始后写入 UTC `started_at` 并进入 `in_progress`。`pending` 需先确认；`cancelled`、`completed`、`exception` 为终态。
- Checklist、文本保存和照片上传仅允许 `in_progress`。照片事项由实际上传自动完成，不允许手工伪造；其他事项可逐项更新。
- 完成前所有 `required=True` 事项必须完成；若必做事项含 `photo`，还必须确有照片。完成写入 UTC `completed_at` 与 `completed`。
- 标记异常仅允许 `in_progress`，必须提供非空异常说明，写入 UTC `completed_at` 与 `exception`；允许保留尚未完成的 Checklist。
- 任一任务开始后，未取消/未完成订单进入 `in_progress`；全部非取消任务完成且至少存在一个已完成任务时，订单自动 `completed`；存在异常或未完成任务时订单保持 `in_progress`。订单取消状态不由执行 API 覆盖。
- P7 尚未实现；本轮通过写入真实 Task/Order 状态为未来工作台提供同步数据源，不制造静态统计。

### API 与隐私

- 新增 `/api/admin/tasks/{task_id}` 详情及 start/checklist/notes/photos/complete/exception 写接口；错误使用 `404/409/413/415/422` 等明确状态。
- 单任务后台详情只返回该任务现场需要的数据：完整地址、联系信息、门禁/钥匙、关联猫咪服务要求、Checklist、执行文本、照片资源 ID/URL、订单进度；不返回其他客户/订单数据、服务器绝对路径或原始文件名。
- 当前尚无 P12 鉴权，README 必须继续明确 `/admin` 与 `/api/admin/*` 只可在本机/私网使用，不得对公网开放。

### 图片存储

- 本地根目录为 `data/uploads`，任务照片按日期分层，磁盘文件名使用服务端 UUID；数据库只保存 `/uploads/...` 形式的相对 URL。
- 仅接受内容与声明类型一致的 JPEG、PNG、WebP；拒绝空文件、SVG、HTML、脚本、伪造类型和损坏图片。
- 单文件最大 10 MiB、最大 25,000,000 像素；使用 Pillow 解码验证并在读取后关闭对象，不依赖扩展名。
- 写入使用临时文件后原子改名；路径解析必须保持在上传根目录内。数据库失败或并发 revision 失效时清理新文件。
- 图片通过受控的 `GET /api/admin/tasks/{task_id}/photos/{photo_id}` 返回，并校验 task/photo 关联；不挂载公共任意目录。完成、异常或取消后不提供删除接口。

### 前端

- 注册 `/admin/tasks/:id`，提供加载、错误、开始、Checklist、照片上传/预览、备注、猫咪状态、异常说明、完成和只读终态。
- 计划页任务详情提供“进入执行/查看执行记录”入口；P6 页面保留返回订单计划的路径。
- 所有写操作在成功后采用服务端返回的新 revision；`409` 给出刷新提示，禁止旧页面继续覆盖。
- 保持当前功能优先的轻量 UI，不提前复制手机端或进行重度视觉重构。

## 验收标准

- 合法任务可从计划页进入 `/admin/tasks/:id`，按“开始 → Checklist/文本/照片 → 完成”闭环，刷新后数据完整保留。
- 异常路径可记录原因并进入只读异常终态；非法转换、必做未完成、旧 revision、错误 task/item/photo 关联均被拒绝且无部分写入。
- 任务开始/完成/异常能按规则同步订单进度；多任务订单仅在最后一个非取消任务完成时自动完成。
- 合法三种图片可上传和受控读取；空、超大、超像素、伪造或损坏内容被拒绝；响应和数据库不泄漏本机路径/原始文件名。
- 执行历史继续锁定 P3 订单结构重建、P4 排程和 P5 路线快照。
- 所有新增运行时图片和临时文件都被 `.gitignore` 排除；staged diff 不含敏感数据、真实 Key、数据库或上传内容。
- Windows `setup.bat` 可安装新增依赖；`start.bat` 后 API、`/admin/tasks/:id` 和图片读取可用，`stop.bat` 后 8000/5180 无残留监听。
- 后端全量测试、前端 lint、typecheck、全量测试、生产构建、`compileall`、Alembic check、`git diff --check` 全部通过。
