# P18：修复订单、路线、客户档案与日结收款闭环

## 背景

当前订单新建、客户归档、路线定位和收款仍是彼此割裂的流程：订单表单没有复用标准门禁选项，金额编辑不明显，直接录入的客户不会进入客户档案，路线只在手动生成时才尝试定位，收款只能按整单余额登记。此外，系统演示数据和真实业务数据缺少可审计的隔离清理入口。

## 目标

- 新订单默认按服务日期日结，同时兼容历史整单结算。
- 订单金额由每次价格和指定日期的单笔加收或减免组成，全部由后端重算。
- 直接录入订单时自动、可解释地匹配或创建客户档案，不创建占位猫咪。
- 订单和任务先保存，再自动定位地址；定位失败不能回滚订单。
- 订单可以精确跳转到对应服务日期和任务的路线工作区。
- 收款支持按日多次部分收取并保护已收日期的金额完整性。
- 精确预览并永久清理 `catcare-demo-seed-v1`，用系统标记阻止演示数据再次播种。
- 对当前订单 #2 做一次有前置条件的业务数据修复，并保留可恢复数据库备份。

## 允许修改范围

- `backend/app` 下的模型、Schema、服务、API、数据库种子与运行时装配。
- `backend/migrations/versions` 下新增的 `0009` 迁移。
- `backend/tests` 中与 P18 行为相关的测试。
- `frontend/src` 下订单、路线、客户档案、收款及演示数据清理相关页面、类型、API 和测试。
- 本任务文档及必要的忽略规则。

## 禁止修改范围

- 不提交或输出 `.env`、API Key、Token、Cookie、浏览器数据和数据库内容。
- 不把地图密钥写入源码；浏览器街道底图继续由现有环境配置提供。
- 不新增退款、通用收款流水编辑或删除功能。
- 不改变历史订单快照语义；修改客户档案不得反写历史订单。
- 不删除非 `catcare-demo-seed-v1` 精确关联的数据。
- 不强推、不重写 Git 历史、不改变仓库可见性或权限。

## 已确定实现要求

1. `Order` 新增 `settlement_mode` 和单笔指定服务日期的加收/减免；新订单默认 `daily`，迁移中的历史订单保持 `order_total`。
2. `Payment.service_date` 可空：日结订单必须填写订单内日期，整单订单必须为空；同日允许多次部分收款，但累计不得超过当日余额。
3. 一旦已有收款，禁止切换结算模式、删除已收日期或降低对应日期应收；revision、并发冲突和超额保护继续生效。
4. 订单表单复用标准入户方式和钥匙状态下拉，兼容历史自由文本；钥匙编号是独立文本框。
5. 客户匹配顺序为唯一电话、唯一微信、姓名加完整地址。唯一命中时恢复已归档档案并只补空字段；多命中返回候选并要求选择；无命中时事务内创建客户。
6. 猫咪数量只用于订单快照；不创建“猫咪1”等占位档案，客户档案显示仍待补齐的猫咪数量。
7. 订单和任务提交成功后自动地理编码。失败只记录状态并可重试；只向地图服务发送上门地址。
8. 地址变化时清空旧坐标并重试；客户地址与订单地址一致时同步坐标缓存。
9. 路线链接携带 `date` 和 `task_id`；路线页默认最近有效服务日，排除已取消任务，并区分同步、定位、路线和底图状态。
10. 演示清理先预览数量，再二次确认；支付先删、再删任务/订单/猫咪/客户，最后写入系统标记。
11. 当前 SQLite 必须先备份，再迁移；订单 #2 的误登记 ¥60 流水只在精确前置条件成立时删除并恢复为两日各待收 ¥30。

## 验收标准

- 空库及 `0008 -> 0009` 迁移成功，外键检查无错误，历史订单仍可按整单收款。
- 新建订单默认日结，金额调整、每日应收和订单总应收一致。
- 客户唯一匹配、歧义、创建、恢复归档和只补空字段均有后端测试。
- 订单保存不受地图失败影响；重试定位可更新订单、任务和匹配客户坐标。
- 日结和整单都支持部分收款，日结超额、错日期、缺日期和并发冲突均被拒绝。
- 演示清理只影响系统标记数据，清理后再次 seed 不恢复。
- 前端下拉、金额首屏、调整日期、路线跳转、定位状态、客户提示和每日待收均有测试。
- 当前数据中订单 #2 关联客户、无占位猫、26/27 日任务存在、日结待收各 ¥30，地址定位状态可解释。
