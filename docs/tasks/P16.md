# P16：订单主导、客户审核与 GPT 路线重构

## 背景

当前工作树已包含 P15 流程简化、本机免登录和橘色视觉改造，且存在大量未提交修改。本任务必须在其上增量实现，不得 reset、stash、恢复已删除鉴权文件或改写真实 `.env`、默认业务数据库。

## 目标

- 主导航固定为工作台、订单管理、路线图、收款记录、客户档案、设置。
- 订单保存现场执行快照，不再依赖客户档案的实时内容。
- 客户提交可由管理员编辑、定价并一次确认落档与生成订单。
- 为客户和订单提供有历史保护的安全删除或归档。
- 使用 GPT-5.6 Sol 产生匿名路线顺序建议，高德继续提供坐标、真实道路、里程、耗时和底图。

## 允许修改范围

- 与客户、订单、填写审核、计划、地图、执行、工作台、收款和设置直接相关的后端模型、Schema、API、服务与测试。
- 新增基于 `0007_simplify_customer_orders` 的数据库迁移。
- 直接相关的前端页面、路由、类型、API、测试和必要的共享 UI。
- `.env.example`、README、开发进度和本任务文档。

## 禁止修改范围

- 不恢复登录、会话、角色守卫或访问码管理。
- 不读取、输出、提交或通过前端保存 API Key、Token、Cookie、真实 `.env` 内容。
- 不直接修改默认业务数据库，不删除现有客户、订单、任务、照片或收款。
- 不提交、推送、部署、安装系统级软件或操作远程服务器。
- 收款流水继续保持追加-only，不实现删除、退款或撤销。

## 已确定实现要求

- 订单保存联系人、地址、入户/钥匙、客户备注、猫咪详情、地理编码和来源客户 ID 快照；运行时页面读取快照。
- 订单、任务、收款到客户的外键改为可空 `SET NULL`，移除会级联删除历史业务数据的 ORM 级联。
- 直接订单的姓名为普通文本输入；客户档案复用通过独立操作完成；缺少地址时明确禁止自动路线。
- 审核保存使用独立 `review_payload` 和管理员 `unit_price`，不得覆盖客户原始提交；最终转换创建已确认订单。
- 无收款且无执行历史的订单可永久删除；有历史只能取消。无业务关联客户可永久删除，有历史客户可归档/恢复。
- `/admin/orders` 和 `/admin/routes` 为独立页面；旧 `/admin/plans` 兼容重定向。
- 高德后端、浏览器底图和 GPT 推荐分别显示状态；不得把“配置存在”显示为“已连接”。
- OpenAI 调用使用服务端 Responses API、`gpt-5.6`、严格 JSON Schema、`store=false`；只发送匿名任务 ID、行驶矩阵、计划时间和服务标志。
- GPT 输出必须是完整无重复排列；缺 Key、失败、非法输出或超过 20 站时回退本地最近邻。

## 验收标准

- 老订单迁移后在客户修改、归档或外键置空时仍能用于订单、计划、地图、执行、工作台和收款。
- 客户填写原稿保留，管理员可编辑审核稿和单价，转换失败无半套数据。
- 安全删除规则在 API 和 UI 两侧一致，任何有收款或执行历史的订单都不能物理删除。
- 导航顺序、独立页面、兼容重定向、纯文本姓名和显眼单价满足确认方案。
- 地图错误能区分配置、权限、配额、网络和地址解析；GPT 回退来源可见且路线指标仍来自高德。
- 不出现范围外修改、真实密钥、TODO/debug、临时文件或新的鉴权回归。
