# P5｜地图与路线执行任务

## 背景

P0–P4 已建立 Windows 本地后台、数据库、客户/多猫、订单自动生成任务，以及 `/admin/plans` 的按天排程三栏页面。正式开发文档要求 P5 将中栏从路线顺序占位升级为真实地图能力，并通过 Adapter 隔离地图厂商。

现有 `Customer.latitude`、`Customer.longitude`、`Customer.geocode_status`、`Task.planned_lat`、`Task.planned_lng`、`Task.sort_order` 和 P4 日计划修订值足以覆盖本轮，不新增路线缓存表或业务迁移。首个厂商实现选择高德开放平台；后端 Web 服务 Key 与前端 JS API Key 均只从本机环境读取，不写入代码或数据库。

## 目标

1. 建立业务层可替换的 `MapProvider`、`GeocodeProvider`、`RouteProvider` 和 `NavigationProvider` 契约，并提供高德适配器及明确的未配置状态。
2. 将客户文字地址按需解析为坐标并缓存到已有 Customer 字段，避免每次进入计划页重复解析。
3. 为当日未取消任务返回起点、Marker、真实路线折线、总距离、预计行驶时间和外部导航链接。
4. 基于坐标给出稳定、可解释的简单推荐顺序，并用地图路线服务计算推荐路线的真实距离与时间。
5. 支持一键采用推荐顺序，复用 P4 的完整日排程保存、修订值和执行历史锁定规则。
6. 在没有 Key、缺少起点、地址无法解析、网络超时或地图服务失败时清晰降级，绝不生成伪造坐标、路线、距离或用时。

## 允许修改范围

- `backend/app/maps/`：地图契约、配置工厂、高德适配器和错误边界。
- `backend/app/services/plan_routes.py`：当日 Marker、按需地理编码、路线与推荐编排。
- `backend/app/api/plans.py`、`backend/app/schemas/plan.py`、`backend/app/services/plans.py`：P5 路线 API、响应模型及修订值协作。
- `backend/app/api/customers.py`：客户地址变化时使已缓存客户坐标失效。
- `backend/requirements*.txt`：仅补充实际运行所需的通用 HTTP 客户端依赖。
- `backend/tests/`：Provider、路线 API、缓存、并发、隐私与回归测试。
- `frontend/src/features/plans/`：路线 API/类型、地图渲染 Adapter、Marker、指标、推荐与采用交互。
- `frontend/src/vite-env.d.ts`、`frontend/vite.config.ts`：P5 本机前端地图配置类型和根目录环境文件读取。
- `.env.example`、`README.md`、`DEVELOPMENT_PROGRESS.md` 和本任务文件。

## 禁止修改范围

- 不在订单、计划或客户业务代码中直接调用高德 SDK/HTTP API；厂商细节只能存在于 Adapter。
- 不把任何真实 Key、Security Code、家庭起点、客户地址、坐标、数据库、上传照片、`.env`、日志或 `.runtime` 文件提交到 Git。
- 不把后端 Web 服务 Key返回给浏览器，不在错误信息中输出带 Key 的请求 URL或原始第三方响应。
- 不把姓名、手机号、微信、门禁、钥匙、房号、客户备注或照片路径发送给地理编码/路线服务；地理编码只使用小区、地址和楼栋，路线服务只使用坐标。
- 不在页面初次加载时自动把客户地址发送给第三方；必须由用户明确点击“生成/刷新路线”。
- 不开发复杂 TSP、实时调度、车辆队列、多起点、多员工、路线历史或计费系统。
- 不改变 P4 的 `sort_order` 权威语义，不绕过完整日计划校验、修订冲突或执行历史锁定。
- 不实现 P6 执行 Checklist/照片/完成流程、P9 手机端与一键导航流程、P12 完整鉴权或 P14 重度 UI 重构。

## 已确定实现要求

### Provider 与配置

- 后端业务编排只依赖四类 Protocol；高德实现组合这些能力，后续可替换百度或腾讯实现。
- `CATCARE_MAP_PROVIDER` 默认 `disabled`；首个支持值为 `amap`。
- 高德后端读取 `CATCARE_AMAP_WEB_KEY`、`CATCARE_HOME_LATITUDE`、`CATCARE_HOME_LONGITUDE`、可选 `CATCARE_MAP_CITY` 和请求超时。Web Key 永不进入 API 响应。
- 前端高德底图独立读取 `VITE_AMAP_JS_API_KEY` 和可选本机 `VITE_AMAP_JS_API_SECURITY_CODE`。未配置 JS Key 时，仍用 Provider-neutral 坐标画布展示后端返回的真实 Marker/折线，并明确说明没有街道底图。
- 根目录 `.env.example` 只包含空值和说明；真实 `.env` 继续被 `.gitignore` 排除。
- 采用高德官方 Web 服务地理编码、驾车路径规划和 URI 导航协议；HTTP 请求设置有限超时并将第三方失败转换为不泄密的本地错误。

### 地址缓存与坐标快照

- 客户地址由 `community + address + building` 去重组合；不发送客户姓名、单元、房号、联系方式、门禁或钥匙信息。
- 客户已有合法经纬度时直接复用；地理编码成功写入 Customer 坐标和 `resolved` 状态，查无结果写入 `failed`，缺少可解析地址标记为 `missing`。
- 用于地理编码的客户小区、地址或楼栋实际发生变化时清空 Customer 坐标，并将状态置为 `pending` 或 `missing`；单元、房号等未发送给地图服务的字段变化不触发重解析，历史 Task 坐标不批量覆盖。
- 未产生执行历史的任务在路线刷新时把有效客户坐标写入 `planned_lat/planned_lng`，作为本次计划地点快照；已有执行历史的任务只读取原快照，不覆盖。
- 日计划修订值纳入任务计划坐标和预计到达字段，路线刷新后的前端必须使用新修订值，避免旧页面一键采用覆盖并发变化。

### 路线工作区 API

- `GET /api/admin/plans/{service_date}/route` 只读取本地缓存，返回 Provider 状态、起点、已解析 Marker、未解析原因、导航链接和当前修订值，不发起第三方请求。
- `POST /api/admin/plans/{service_date}/route/preview` 必须提交当前日计划修订值；用户触发后才解析缺少坐标的地址并计算路线。
- 空日期返回 `404`；旧修订值返回 `409`；未配置 Provider/起点返回 `503`；超时、HTTP、非法响应或厂商错误返回去敏后的 `502`。
- Marker 批量响应只包含任务 ID、顺序、客户显示名/小区、坐标和无 Key 的导航 URL；不包含完整地址、联系方式、门禁、钥匙、备注或照片。
- 当日已取消任务不进入地图路线；重复拜访同一客户仍按 Task 保留为独立站点。
- 地址无法解析时允许返回其余已解析站点的当前路线，但明确列出未解析任务；存在未解析任务时不允许采用不完整推荐。

### 路线、推荐与采用

- 当前路线严格使用 P4 的 `sort_order`；高德驾车 API 返回的距离、时间和折线才可显示为真实指标。
- 推荐顺序采用简单、稳定的最近邻启发式，距离依据坐标，等距时保持原顺序/任务 ID 稳定；算法放在 RouteProvider 适配层，不进入业务页面。
- 推荐顺序必须再通过 RouteProvider 计算真实路线指标，页面同时展示当前与推荐结果，不把启发式直线距离冒充道路里程。
- 推荐结果覆盖所有可规划任务；取消或未解析任务保持原相对槽位。只有全部未取消任务已解析、排程未锁定且推荐顺序确实变化时才启用“一键采用”。
- 一键采用直接复用 `PUT /api/admin/plans/{date}/schedule`，提交当天全部任务和原计划时间；成功后列表、Marker 顺序和修订值同步更新。
- 路线 API 只预览和采用顺序，不删除任务、不重建事项、不修改任务状态，也不写入伪造的预计到达时间。

### 页面交互与降级

- 中栏显示 Provider 状态、隐私提示、生成/刷新路线按钮、起点、可点击编号 Marker、真实路线折线、总距离和预计行驶时间。
- 点击 Marker 与左侧点击任务使用同一选中状态；已解析任务可从右侧打开高德 URI 导航链接，但完整手机执行导航闭环留到 P9。
- 页面初次加载只读取本地缓存；用户点击按钮前不调用地图厂商。
- 没有后端 Key/起点、没有前端 JS Key、断网、地址缺失或解析失败均显示可操作说明；保留人工排序能力。
- 有未保存人工排程时禁止刷新路线或采用推荐；采用推荐后立即持久化，不再要求第二次点击保存。

## 验收标准

1. 四类 Provider 契约存在，计划业务与 React 页面不直接拼接高德 Web 服务 URL；高德适配器可被测试替身替换。
2. 首次显式刷新可解析缺少坐标的客户、缓存 Customer 坐标并写入未执行 Task 快照；再次刷新不重复地理编码。
3. 客户地址实际变化会使 Customer 缓存失效；不变字段更新不会清空坐标；执行历史 Task 坐标不被覆盖。
4. 两个及以上任务能显示真实 Marker、路线折线、当前总距离和时间；地图响应不含手机号、门禁、钥匙、房号、客户备注、照片路径或后端 Key。
5. 当前路线按人工顺序计算，推荐路线返回稳定的完整任务顺序和真实 Provider 路线指标。
6. 一键采用推荐后 `sort_order` 连续且刷新保持；旧修订值、任务缺失或执行历史锁定仍返回 `409` 且不部分写入。
7. 空日、取消任务、重复客户、单任务、缺失地址、部分地理编码失败、未配置、超时、厂商错误和非法响应均有确定行为。
8. 未配置高德时页面明确降级且不显示假指标；仅缺少 JS Key 时仍可用真实坐标画布查看 Marker/折线。
9. Marker 点击联动右侧详情，导航 URL 不含 Key；生成路线前页面明确提示会把精简地址/坐标发送给地图服务。
10. Windows 临时数据库通过 Vite 代理验证路线状态、未配置降级、P4 排程回归及启停清理；真实厂商解析由 Mock Transport/Provider 自动测试验证，不依赖提交 Key。
11. P0–P4 后端、前端、迁移、Seed、路由和构建回归全部通过，无未说明迁移和范围外依赖变化。

## 返回格式

完成后返回：

1. 四类 Adapter、高德实现、配置和无 Key 降级摘要。
2. 地址缓存、任务坐标快照、当前/推荐路线与一键采用规则。
3. 地图/Marker/指标/导航交互和隐私边界。
4. 自动测试、Windows 联通、浏览器布局与交互证据。
5. Git 差异、迁移、依赖、敏感数据和临时文件审计结论。
6. P5 提交哈希和下一轮 P6 边界。
