# P9｜手机执行端任务文件

## 背景

P0-P8 已完成 Windows 本地 Web 管理后台、客户与多猫档案、订单、按天计划、地图路线、任务执行、工作台和收款登记。当前 `/mobile` 仍是占位页，但 P4 已提供每天独立排序的 Task，P5 已提供缓存坐标和 provider-neutral 导航链接，P6 已提供带 revision 的任务执行状态机、Checklist、文字记录、照片上传和完成校验。

正式依据为《猫咪喂养登记系统-开发执行文档.md》第 3.2、11 节与 P9：手机端只做今天任务、当天路线、任务详情、导航、Checklist、图片上传和完成任务，不复制完整 PC 后台。P11 才负责 PWA，P12 才负责登录、角色与权限隔离。

## 目标

- 将 `/mobile` 升级为可在手机浏览器使用的今日执行首页。
- 按 P4 已保存的 `sort_order` 展示当天路线和每一次上门任务，不在手机端编辑计划或重新规划路线。
- 为移动端建立最小化批量摘要和单任务现场详情 API，避免在今日列表批量暴露地址、电话、门禁、钥匙或照片。
- 在 `/mobile/tasks/:id` 完成开始任务、Checklist、现场文字、拍照上传和完成任务闭环。
- 复用 P5 导航链接与 P6 状态机、revision 和上传校验，不复制业务规则或照片存储。
- 保持 Windows 本地与可信局域网运行；清楚提示当前尚无正式鉴权，不允许作为公网入口部署。

## 禁止修改范围

- 不实现完整客户、订单、计划、收款或设置后台，不在手机端新增、删除或重排任务。
- 不实现路线推荐、坐标解析、折线地图或路线持久化；手机端只读取 P4 顺序与 P5 已缓存坐标生成的单站导航链接。
- 不实现离线队列、Service Worker、manifest、安装图标、standalone 或添加到主屏幕；这些属于 P11。
- 不实现登录、会话、设备绑定、角色、执行人员分配、Token、正式权限隔离或公网部署；这些属于 P12。
- 不实现异常结单新入口；已有异常状态只读展示，避免在 P9 扩大现场操作范围。
- 不修改数据库模型、Alembic 迁移、P6 状态机、照片存储格式或收费逻辑。
- 不新增依赖、不更换技术栈、不进行无关重构或重度 UI 设计。
- 不在批量响应中返回电话、详细地址、门禁、钥匙、订单备注、猫咪医疗/服务细节、照片 URL、磁盘路径或原始文件名。
- 不提交 `.env`、数据库、上传、日志、构建产物、`.runtime`、真实业务数据或本机绝对路径。
- 子代理不得修改源文件、提交 Git、联网、读取 secrets、访问项目外路径或调用其他代理。

## 已确定实现要求

### 移动 API 与今日任务

- 新增独立 `/api/mobile` 路由命名空间；它是为 P12 预留清晰边界，不代表 P9 已完成鉴权。
- `GET /api/mobile/today` 默认由服务端按固定 Asia/Shanghai 计算业务日期；仅允许可选 `date=YYYY-MM-DD` 用于确定性测试和本地排查，手机 UI 不提供日期切换。
- 响应返回业务日期、任务总数、待执行数、已完成数和按 `sort_order、id` 排序的任务摘要。
- 每次上门 Task 都独立保留，同一订单同日多次服务不得按订单去重。
- 取消 Task 或取消订单不进入行动列表；completed 与 exception 保留为今日历史并只读展示。
- 批量任务摘要只含任务/订单 ID、顺序、计划时间、状态、客户姓名、小区、猫数量和可选导航链接。
- 导航只使用 Task 已缓存的 P5 坐标与当前地图 Provider 生成 URI；不得在读取今日任务时联网解析地址或预览路线。无坐标、Provider 未配置或生成失败时返回 `null`，UI 仍显示文字任务并解释不可导航。
- 导航 URI 不包含地图 Web Key，手机端以普通外部链接打开。

### 单任务详情与执行

- `GET /api/mobile/tasks/{task_id}` 返回 P6 现场执行详情；敏感地址、电话、门禁、钥匙和猫咪要求只在用户主动进入单个任务时返回。
- 新增移动端开始、Checklist 更新、备注/猫咪状态保存、照片上传/读取和完成接口；所有写入直接调用 P6 service，不复制状态判断。
- 每次写入必须提交 64 位 `expected_revision`，旧 revision 保持 409；成功后返回新详情和 revision。
- 仅 confirmed/ready 可开始；仅 in_progress 可修改 Checklist、文字和照片；完成前仍必须满足 P6 必做事项与必做照片校验。
- 终态任务只读展示，不显示可写控件；pending/cancelled/completed 订单不能通过移动端绕过 P6 规则开始。
- 移动详情的照片 URL 必须指向 `/api/mobile/tasks/...`；原有 admin 详情继续返回 `/api/admin/tasks/...`，不得造成 P6 回归。
- 上传继续使用现有 JPEG/PNG/WebP 内容、MIME、10 MiB 与像素上限校验；前端文件输入添加图片 MIME 与 `capture="environment"`，但允许相册选择。
- 图片读取继续使用 `private, no-store` 与 `nosniff`；不返回磁盘路径或原始文件名。

### 移动前端

- `/mobile` 显示上海业务日期、任务总览、按顺序的“今日路线”和任务卡片，包含加载、错误、刷新、空状态。
- 首页任务卡展示顺序、计划时间、客户、小区、猫数量、状态、进入任务按钮；有导航 URI 时显示一键导航，无 URI 时显示明确不可用原因。
- `/mobile/tasks/:id` 展示返回首页、刷新、客户联系与完整地址、导航、入户/门禁/钥匙、猫咪资料与服务要求、Checklist、现场文字、照片和完成按钮。
- confirmed/ready 状态显示开始按钮；in_progress 显示编辑控件；终态与不可开始状态只读。
- 每次操作串行执行并禁用重复提交；失败保留当前页面并展示后端错误；成功以服务端返回详情刷新 revision。
- 页面针对至少 320px 宽度设计，按钮和表单适合触摸，不引入 PC 管理后台侧栏或复杂地图。
- 页面显著提示“当前仅适用于本机或可信局域网，正式登录与权限将在 P12 完成”。

## 验收标准

- 空库、正常今日任务、同日多次服务、取消任务/订单、completed/exception 历史均有自动化证据，排序与计数正确。
- `date` 默认值采用 Asia/Shanghai，测试可固定日期，不依赖浏览器本地时区。
- 批量接口不含电话、详细地址、门禁、钥匙、订单备注、猫咪细节或照片；单任务接口只在进入指定任务后提供现场必需信息。
- 有缓存坐标与可用 Provider 时生成不含 Key 的导航 URI；无 Key或无坐标时任务仍可执行且没有假链接。
- 移动端能完成开始、Checklist、文字、真实图片上传和完成闭环；P6 revision、状态机、必做事项和图片校验保持有效。
- 移动照片 URL 使用 mobile 路径，admin 原路径与 PC 执行页无回归。
- `/mobile` 和 `/mobile/tasks/:id` 在 390×844 手机视口无横向溢出，核心信息与触摸操作可见；刷新与返回路径正常。
- P9 没有新增迁移/依赖，没有实现 P10-P14 功能，也没有暴露本机路径、密钥或真实数据。
- 后端全量测试、前端 lint/typecheck/全量测试/生产构建、`compileall`、Alembic current/check、`git diff --check` 全部通过。
- Windows 启停、临时 SQLite、API 代理联通与手机浏览器可见验收通过；测试后端口、上传图片和 P9 临时数据清理完成。
