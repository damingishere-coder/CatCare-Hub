# P11｜响应式与 PWA 任务文件

## 背景

正式依据为《猫咪喂养登记系统-开发执行文档.md》第 3.2、20 节与 P11。P9 已完成轻量手机执行端，P10 已完成客户填写端；本轮补齐基础安装能力与小屏验收，不把手机端扩展成完整后台，也不提前实现 P12 登录权限或高级离线业务。

## 目标

- 让生产构建具备有效的 Web App Manifest、应用图标、`standalone` 展示和 `/mobile` 安装入口。
- 注册基础 Service Worker，使已联网加载过的生产构建在断网时仍能打开无业务数据的应用壳。
- 在手机执行首页提供浏览器支持时可触发的“添加到主屏幕”入口，并保留通用安装提示。
- 验证 `/mobile`、`/mobile/tasks/:id`、`/fill/:token` 的移动端布局；桌面后台继续 PC 优先且不得因 P11 退化。

## 允许修改范围

- `frontend/public/` 下 PWA manifest、Service Worker 和不含业务数据的应用图标。
- `frontend/index.html` 的 PWA 元数据。
- `frontend/src/pwa/` 的注册逻辑和测试。
- `frontend/src/features/mobile/` 的安装提示与直接相关测试、少量响应式修正。
- `frontend/vite.config.ts`、`frontend/package.json`，仅限不新增依赖的生产预览与验证配置。
- `README.md`、`CURRENT_STATE.md`、`DEVELOPMENT_PROGRESS.md` 和本任务文件。

## 禁止修改范围

- 不修改后端业务、数据库模型、迁移、API、鉴权或生产数据。
- 不新增 PWA/Workbox/离线数据库依赖，不更换 React、Vite、Tailwind 技术栈。
- 不实现离线写入、照片离线上传、后台同步、冲突合并、推送通知或地图瓦片缓存。
- 不缓存任何 `/api/*`、`/fill`、`/fill/:token`、上传或照片响应，不在 Cache Storage 中保存业务 Payload、Token、手机号、地址、门禁或钥匙信息。
- 不把局域网 HTTP 宣称为可安装的安全上下文，不提前实现 P12-P14。
- 不重做桌面后台 UI，不将手机端复制为完整后台。

## 已确定实现要求

- Manifest 使用 `id`/`start_url` 为 `/mobile`、根 scope、`display: standalone`、中文名称、主题色和纵向优先方向。
- 提供至少 192×192、512×512 两个本地 PNG 图标；图形为通用 CatCare-Hub 标识，不使用客户照片或业务截图。
- Service Worker 使用版本化应用壳缓存；安装时从生产 `index.html` 发现带 hash 的 `/assets/*` 并预缓存，更新时清理旧版本。
- Service Worker 只处理同源 GET；API、客户填写路径、上传和照片路径直接绕过。导航失败时只回退到不含业务数据的 `index.html`，静态资源使用当前版本缓存。
- 不调用 `skipWaiting()` 强制切换正在执行任务的页面；新版本在正常刷新/关闭旧页面后接管。
- 仅在生产构建和安全上下文中注册 Service Worker，开发服务器和 Vitest 不注册，避免旧缓存污染开发。
- 安装按钮只在浏览器提供 `beforeinstallprompt` 时出现；不支持时显示浏览器菜单提示，standalone 模式不重复提示。
- README 明确：离线仅是应用壳，任务数据和写入仍需网络；手机通过普通局域网 HTTP 访问时通常不能安装，需 localhost 或后续 HTTPS。

## 验收标准

- 生产构建输出 manifest、Service Worker、192/512 图标，manifest 字段与图标尺寸有效。
- Chromium 在 localhost 生产预览下成功注册 Service Worker；manifest、图标和 `/mobile` 均返回 200。
- 首次联网加载并由 Service Worker 接管后，断网打开 `/mobile` 仍显示应用壳，并明确显示 API 加载失败，不展示伪造或旧业务数据。
- Cache Storage 中没有 `/api/`、`/fill/`、上传、照片或包含 Token 的缓存键。
- 390×844 下 `/mobile`、任务页和客户填写页无水平溢出；1440px 后台布局保持桌面侧栏。
- 安装提示的支持、不支持和 standalone 状态有自动化覆盖。
- 前端 lint、类型检查、全量测试和生产构建通过；后端全量测试保持通过。
- Git 只包含代码、静态通用图标、配置与文档，无数据库、日志、上传、`.env`、真实数据或新增依赖。

## 测试命令

```powershell
npm run lint --prefix frontend
npm run typecheck --prefix frontend
npm test --prefix frontend -- --run
npm run build --prefix frontend
.\.venv\Scripts\python.exe -m pytest backend\tests -q
```

生产预览和浏览器验证使用隔离端口与既有本地 API；测试后必须停止进程、检查 8000/预览端口无监听，并精确清理本轮临时日志或数据库。

## 返回格式

- `summary`：实现结果、范围和非目标。
- `commands`：实际命令、退出码、测试数量和构建结果。
- `browser`：manifest、Service Worker、缓存隐私、离线壳与响应式证据。
- `privacy_scope`：敏感路径、依赖和范围外修改审计。
- `git`：提交号、提交信息和最终工作区状态。
- `verdict`：`success` 或精确阻塞原因。
