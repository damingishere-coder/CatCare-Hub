# P13 测试与数据验证执行任务

## 背景

P0-P12 已完成客户、多猫、订单、计划、路线、执行、收款、客户填写、PWA 与权限隔离。现有测试对各模块已有较完整的单领域覆盖，但还没有一条在真实 admin/mobile 会话、同一个隔离数据库和同一个临时上传目录中串联主要业务状态的验收链路。正式开发文档要求 P13 至少验证新建客户、多猫、订单、自动任务、跨天与每日多次、排序、执行完成、收款/待收款、客户填写 Token/失效和图片上传。

## 目标

1. 新增可重复的 P13 后端集成验收，使用完全虚构数据串起核心业务闭环。
2. 验收必须经过 P12 的真实角色会话：admin 操作后台，mobile 执行现场任务，fill Token 保持匿名能力边界。
3. 所有数据库、上传和访问码配置只存在于 pytest 临时目录或测试进程环境，绝不读取真实 `.env`、默认数据库或真实照片。
4. 明确记录 P13 场景矩阵，并让后端全量、前端全量和 Windows 构建继续通过。

## 允许修改范围

- `backend/tests/`：新增 P13 集成验收及必要的测试辅助函数。
- `docs/tasks/P13.md`、`README.md`：记录本轮范围、证据和当前阶段。
- 仅当集成验收证明生产逻辑确有缺陷时，允许由主代理做最小生产修复；不得为让测试通过而放宽断言。

## 禁止修改范围

- 不改变 React + TypeScript + Vite + FastAPI + SQLAlchemy + SQLite/Alembic 技术栈。
- 不重构 P0-P12 业务实现，不引入新依赖，不提前做 P14 UI/UX 重构。
- 不读取、复制或修改根目录真实 `.env`、默认 `data/catcare.db`、真实上传、客户资料或运行日志。
- 不使用真实手机号、地址、门禁、钥匙、访问码、客户 Token 或照片；测试值必须带明确的 `P13` 虚构标识。
- 不启动长期服务，不部署、不 push、不对外写入。

## 已确定实现要求

### 隔离测试上下文

- 使用 `migrated_database_url` 提供的 pytest 临时 SQLite，并显式覆盖 FastAPI `get_db`。
- 使用 `tmp_path` 覆盖任务上传根目录；测试结束后由 pytest 清理。
- 使用进程内虚构 admin/mobile 访问码哈希，启用 `real_auth_dependencies`，禁止依赖业务测试的授权绕过。
- 同一个测试客户端依次验证匿名、admin 与 mobile；角色切换必须显式注销或重新登录。
- 测试入口继续强制 `PYTHON_DOTENV_DISABLED=1`，无显式数据库 URL 时只允许内存数据库。

### 核心业务生命周期

- admin 创建一个虚构客户和两只猫；随后创建 3 天、每天 2 次的订单。
- 验证服务端金额、6 个自动任务、每天 2 个任务和 TaskItem 多猫关联，初始订单保持待收款。
- 读取某日计划，调整时间与排序并保存；重新读取确认持久化，同时用旧 revision 验证冲突被拒绝且不会部分写入。
- mobile 读取并开始任务，保存必填 Checklist/文字，上传内存构造的小型有效 PNG，再完成任务。
- 完成全部任务后验证订单执行状态联动；admin 登记部分收款与尾款，验证待收金额递减至 0、支付状态变为已付且收款记录完整。

### 客户填写 Token 生命周期

- admin 生成一次性展示的填写链接，列表刷新后不得恢复原文。
- 匿名使用正确 Token 保存多猫草稿并提交；错误 Token 返回统一 404，重复提交被拒绝。
- admin 审核并转换，验证产生客户、两只猫、跨天订单和自动任务，重复转换保持幂等。
- 另建 Token 并关闭，匿名访问返回 410；另用已过期 Token 验证 410。
- 数据库只检查 Token 哈希，不保存或恢复 Token 原文。

## 验收标准

1. 新增的 P13 定向集成测试通过，并实际使用 admin/mobile 登录 Cookie 与公开 fill Token。
2. 新建客户、多猫、3 天×2 次订单、6 个任务、排序保存、revision 冲突、任务完成、图片上传、部分/全部收款及待收款均有断言。
3. Token 一次性展示、错误/关闭/过期/重复提交、审核转换、幂等和哈希落库均有断言。
4. 数据库与上传均为 pytest 临时路径；测试不会加载真实 `.env` 或连接默认业务数据库。
5. P0-P12 后端全量测试、前端 lint/typecheck/test/build 和 Python compileall 全部通过。
6. Git diff 不包含依赖变化、数据库、上传、`.env`、日志、临时文件、真实资料、调试代码或范围外修改。

## 测试命令

```powershell
$env:CATCARE_DATABASE_URL='sqlite:///:memory:'

.\.venv\Scripts\python.exe -m pytest backend\tests

git diff --check
git status --short

```

## 返回格式

Operator 只返回：

1. `summary`：成功或失败，以及是否修改任何源文件。
2. `commands`：逐条命令、退出码、测试数量和构建关键输出。
3. `p13_matrix`：客户/多猫/订单/任务/排序/执行/图片/收款/Token 每项证据。
4. `isolation`：临时数据库、临时上传、虚构访问码、`.env` 禁用和 Git 隐私检查。
5. `warnings`：失败重试、环境差异或剩余风险。
6. `verdict`：只陈述验证事实，不代替主代理最终验收。
