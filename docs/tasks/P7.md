# P7｜工作台任务文件

## 背景

P0-P6 已建立 Windows 本地 Web 管理后台、核心业务模型、客户与多猫档案、订单任务生成、按天排程、地图路线和任务执行闭环。正式开发依据《猫咪喂养登记系统-开发执行文档.md》第 5.1 节及 P7 轮次要求开发 `/admin`，让首页真实聚合“今天应该干什么”，并直接消费既有 Task、Order、Payment 权威数据。

当前工作台仍是占位页。现有数据足以计算今日订单、未结束任务、待收款、本月已完成收款、今日安排和多数提醒；但“待发送照片”没有可关闭状态。为避免制造永远存在的假提醒，本轮给 Task 增加独立的照片发送时间，并提供人工“标记已发送”操作，不实际向客户发送照片。

## 目标

- 建立一个隐私最小化的 Dashboard 聚合 API，统一返回业务日期、四项顶部数据、今日安排和可追踪提醒。
- 将 `/admin` 从占位页升级为可用工作台，支持加载、错误、空状态、刷新、任务跳转、快捷入口和照片发送确认。
- 明确定义取消、异常、每日多次任务、订单去重、待收款和 Asia/Shanghai 月份边界，避免重复或静态统计。
- 建立可关闭的“待发送照片”提醒，同时保护 P6 任务 revision 和终态执行历史。
- 保持 P8 收款、P10 客户填写和后续轮次边界，不在 P7 登记收款或生成客户填写 Token。

- 不实现 P8 收款登记、支付编辑、退款或财务报表；P7 只读现有 Order/Payment 数据。
- 不实现 P9 手机执行端、P10 客户填写 Token/提交/审核、P11 PWA、P12 完整鉴权、P13 专项数据验证或 P14 UI Design 重构。
- 不新增通用提醒中心、消息发送服务、短信/微信集成、统计缓存表或后台定时任务。
- 不重构 P2-P6 客户、订单、排程、地图和执行架构，不更换技术栈。

## 已确定实现要求

### 业务日期与顶部数据

- Dashboard 默认按 `Asia/Shanghai` 的当前业务日期计算，并允许只读 `date=YYYY-MM-DD` 参数用于确定性验证；响应明确返回实际业务日期。
- “今日订单”统计当天至少有一项非取消任务、且订单未取消的去重订单数；每日多次任务不能重复计算订单。
- “待执行”统计当天 `pending`、`confirmed`、`ready`、`in_progress` 四种未结束任务；不包含 `completed`、`exception`、`cancelled`。
- “待收款”统计未取消、非退款且 `total_amount - paid_amount > 0` 的订单数。P7 不自行用 Payment 记录修正 Order 金额。
- “本月收入”只汇总 `payment_status=completed` 且 `paid_at` 落在 Asia/Shanghai 当月边界内的 Payment 金额；pending/refunded/无付款时间记录不计入。

### 今日安排

- 返回当天订单未取消、任务未取消的每项 Task；同一订单每日多次必须显示多行。
- 顺序以 P4 权威 `sort_order, id` 为准；展示计划时间、客户姓名、小区、关联猫咪数量和完整任务状态。
- 工作台只返回摘要；点击任务后进入既有 `/admin/tasks/:id` 查看现场敏感详情。

### 今日提醒

- `key_pickup`：当天未结束任务的客户 `key_status` 精确等于规范值“待取”时触发；同一客户当天只显示一次，不根据任意模糊文本猜测。
- `medicine`：当天未结束任务存在未完成 medicine Checklist 时触发；若订单没有 medicine Checklist，但关联猫咪档案标记 `medication_required=True`，也触发档案兜底提醒。已完成 medicine Checklist 不再提醒。
- `photos_pending`：业务日期当天及此前的 `completed` 或 `exception` 任务已有照片且 `photos_sent_at IS NULL` 时持续触发，并携带任务 revision，直到人工标记；不把“未拍照”伪装成“待发送”，也不能让未处理提醒在跨日后消失。
- `payment_due`：对顶部待收款集合逐订单提示客户和待收金额，只链接到 P8 预留收款页，不在本轮登记收款。
- `last_service`：未取消订单 `end_date` 等于业务日期时触发，并关联该订单当天最后一项非取消任务。
- `order_starts_tomorrow`：未取消订单 `start_date` 等于业务日期次日时触发。
- 提醒响应仅返回类型、稳定 ID、必要 task/order/customer 摘要、猫咪数量、金额、消息及照片提醒所需 revision，不返回敏感原字段。

### 照片发送状态

- 在 Task 增加可空 `photos_sent_at`，写入 UTC；迁移支持 SQLite 并保持 PostgreSQL 兼容。
- 新增 revision 保护的“标记照片已发送”接口。只允许已有照片的 `completed`/`exception` 任务；不发送、删除或公开图片，只记录用户已通过外部渠道发送的事实。
- `photos_sent_at` 纳入 P6 任务 revision，避免旧执行页覆盖后台新状态；Task 执行详情只返回发送时间，不返回磁盘路径。
- Dashboard 操作须二次确认；成功后刷新聚合数据并移除对应提醒。并发旧 revision 返回 `409`。

### 前端与快捷入口

- `/admin` 展示四张顶部卡片、快捷入口、今日安排和今日提醒；提供加载、错误、无任务、无提醒、刷新及照片标记 busy 状态。
- 快捷“新增订单”进入 `/admin/plans?view=orders&action=create` 并自动打开现有订单表单；“新增客户”进入 `/admin/customers?action=create` 并自动打开现有客户表单。
- “客户填写入口”只进入现有 `/fill` 预留页，并明确 P10 尚未开放，不能伪装为可生成链接。
- 保持功能优先的轻量布局，不进行 P14 重度视觉重构。

## 验收标准

- 空库和有数据两种情况下 `/api/admin/dashboard`、`/admin` 均稳定可用，无静态假数据。
- 指定日期的今日订单去重、每日多次安排、未结束任务、取消/异常边界、待收款和本月收入均按上述定义计算。
- 六类提醒的触发、不触发、去重和目标关联可由测试证明；照片提醒可经 revision 保护标记已发送并从工作台消失。
- Dashboard 批量响应不包含电话、微信、详细地址、门禁、钥匙编号、备注、照片 URL、服务器路径或原始文件名。
- 快捷新增订单/客户实际打开现有表单；任务行进入现有执行详情；P8/P10 未被提前伪实现。
- P3-P6 订单、计划、路线和任务执行历史保护继续通过回归。
- Windows 启停、临时 SQLite、1440×1000 PC 浏览器可见验收通过；测试结束无端口、临时库或虚构运行数据残留。
- 后端全量测试、前端 lint/typecheck/全量测试/生产构建、`compileall`、Alembic upgrade/current/check、`git diff --check` 全部通过。

- `success` 或 `failure`
- 精确命令和关键输出（测试数、构建模块数、迁移结果、Windows/浏览器结果）
- 实际修改文件清单与迁移说明
- 指标公式、提醒规则、照片发送 revision、日期时区、隐私和范围边界证据
- 任何失败、范围外修改、敏感文件或未解决风险
