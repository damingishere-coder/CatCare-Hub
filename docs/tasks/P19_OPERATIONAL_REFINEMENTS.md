# P19：工作台、订单录入、金额调整与收款纠错

## 背景

当前工作台只展示当日订单，订单地址需要逐项填写，价格输入的原生步进按钮过小；已有收款流水的订单无法调整每次价格，收款流水也缺少纠正误登记的审计入口。按日结算在某日超收、其他日期待收时还会发生跨日期抵消，导致真实待收被隐藏。

## 目标

- 工作台统计当前自然月内有服务日期的非取消订单。
- 订单表单在浏览器本地解析粘贴的中文住宅地址，只填地址字段。
- 每次价格提供大尺寸 `+5/-5` 步进按钮，并继续接受任意非负两位小数。
- 已有收款历史的订单允许修改每次价格，历史收款事实保持不变。
- 按日结算分别展示各日期的待收与超收，不跨日期抵消。
- 收款流水支持带原因和时间的软撤销，保留原始流水且不执行实际退款。

## 允许修改范围

- `backend/app` 下与工作台、订单、收款相关的模型、Schema、服务和 API。
- `backend/migrations/versions` 下新增的 `0010` 迁移。
- `backend/tests` 中与上述行为及迁移相关的测试。
- `frontend/src` 下工作台、订单、收款页面、类型、API、组件和测试。
- 本任务文档及必要的样式调整。

## 禁止修改范围

- 不提交或输出 `.env`、API Key、Token、Cookie、浏览器数据或真实数据库内容。
- 不调用第三方地址解析服务，不记录或持久化用户粘贴的原始地址。
- 不修改、覆盖或删除历史收款金额、方式、日期、备注。
- 不实现真实退款，不把误登记撤销伪装成退款。
- 不物理删除收款流水；存在撤销流水的订单仍禁止永久删除。
- 不在浏览器验收中撤销真实流水或修改现有订单 #2。
- 不强推、不重写 Git 历史、不改变仓库可见性或权限。

## 已确定实现要求

1. Dashboard 将 `today_order_count` 更名为 `month_order_count`，按 `business_date` 所在自然月统计非取消任务关联的去重订单，包含本月未来服务日期。
2. 地址粘贴只在前端本地解析，规范化全角字符、空白和标点，高置信度提取小区、楼栋、单元、房间；不能确定的内容保留在详细地址。
3. 地图查询地址只包含小区、详细地址和楼栋；单元、房间只用于本地完整展示，修改它们不清空坐标。
4. 每次价格步进按钮和键盘上下键按 `5` 增减并保留小数尾数，最低为 `0`；手动输入仍允许任意非负两位小数。
5. 有收款历史时只开放 `unit_price`，继续锁定服务日期、结算方式、金额调整和猫数量；PATCH 与兼容 PUT 使用同一约束。
6. 已收订单改价不修改任何 Payment 或 `paid_amount`，只重算应收、待收、超收和状态；使用 `financial_revision` 防止并发覆盖。
7. 按日应收逐日计算 `due_amount` 与 `overpaid_amount`，订单级数值分别求和，允许两者同时大于零。
8. Payment 新增 `voided` 状态、撤销时间和必填原因；只有 `completed` 可撤销，`pending/refunded/voided` 及重复、过期操作返回 `409`。
9. 撤销事务校验 revision，原子变更流水状态，并以剩余 `completed` 流水重新汇总订单已收、待收、超收和状态。撤销不改变订单业务状态，也不执行外部退款。
10. 收入只统计 `completed`，因此撤销会回溯原收款日期所属收入；撤销后的流水永久保留并继续阻止订单删除。
11. 真实 SQLite 升级前必须创建时间戳备份，并在迁移后执行 `integrity_check` 与 `foreign_key_check`。

## 验收标准

- 当月订单统计覆盖跨月、未来服务日、取消任务和同订单多任务去重。
- 地址解析覆盖常见中文住宅格式、模糊文本、全角字符和手动修正，地图请求不包含单元或房间。
- 价格按钮、键盘、零下限、任意手输金额和非法输入均有前端测试。
- 已收订单涨价、降价、超收和按日混合待收/超收正确，历史流水完全不变，受锁字段不能绕过。
- 撤销整单和按日流水后，收入、待收、超收、状态及提醒正确；重复、并发、待处理和退款状态被拒绝。
- `0009 -> 0010`、空库升级与降级通过，数据库约束、完整性和外键检查无错误。
- 后端完整测试、前端测试、lint、类型检查和构建全部通过。
