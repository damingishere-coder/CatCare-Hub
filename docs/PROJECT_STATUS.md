# 项目状态与路线图

最后核对：2026-08-27。

## 当前结论

CatCare-Hub 是一个**可用的本地优先 V1，持续开发中**。当前代码已经覆盖独立上门喂猫业务从客户资料、订单与排班，到移动执行和收款的主要闭环；项目不声明 production-ready、SaaS、多租户或完整离线能力。

早期 `CURRENT_STATE`、`DEVELOPMENT_PROGRESS` 和开发执行文档已移入[历史档案](history/README.md)。它们记录当时的里程碑，不代表当前实现上限。

## 已实现

- 今日工作台、指标、今日安排、提醒和快捷入口。
- 客户与多猫档案、地址状态、备注和历史关联。
- 多日订单、价格与照护快照、日任务生成、改价和归档规则。
- 按日计划、家 → 客户 → 家闭环、顺序优化、地址校验与 Provider 降级。
- 移动端今日任务、Checklist、照片、异常与完成状态。
- 待收款、部分收款、流水、日结与付款作废审计。
- 一次性客户填写链接、不可变原文、审核草稿、revision、幂等和审计事件。
- 管理端与公开填写端独立构建；CloudBase relay 部署骨架。
- SQLite 启动前检查、备份后迁移、health/ready 与自动化测试。

## 已知限制

- 后台没有账号登录和权限系统，只能在受信任的本机边界使用。
- PWA 缓存应用壳，但业务数据和执行操作仍依赖 API。
- 照片存储在本机文件系统，没有对象存储同步或跨设备复制承诺。
- 收款是记录与审计，不是支付网关。
- AI 和高德为可选集成，配置存在也不等同于外部服务已验证可用。
- CloudBase relay 尚未在本仓库声明真实部署、域名或可用性指标。

## 近期路线图

1. 完善备份发现、恢复演练和用户可读的恢复指引。
2. 在不扩大公网暴露面的前提下完成公开填写部署与撤回手册。
3. 增强端到端测试、失败诊断和运行状态可见性。
4. 持续改善窄屏、无障碍和现场弱网体验。

## 候选方向

- 可选的多用户身份与权限边界。
- 明确同意后的通知集成。
- 更多地图 Provider 和更透明的路线质量比较。
- 安全的跨设备数据同步。

候选方向不是交付承诺。只有代码、测试和真实运行证据齐备后，README 才会把它们移动到“已实现”。
