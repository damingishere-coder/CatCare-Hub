## P5 完成内容

- 建立后端 `MapProvider`、`GeocodeProvider`、`RouteProvider` 和 `NavigationProvider` Protocol，计划业务不直接依赖地图厂商。
- 提供高德 Web 服务与 URI Adapter，覆盖地址转坐标、驾车路线折线、距离/时间、稳定最近邻推荐和无 Key 导航链接；后端 Web Key 不进入浏览器响应。
- 地图配置只从本机 `.env` 读取；默认 Provider 为 `disabled`，无 Key、起点缺失、断网、超时或厂商失败均明确降级，不生成假坐标或假指标。
- 建立只读本地路线工作区和显式路线预览 API；页面初次加载不请求第三方，只有用户点击生成/刷新路线才进行地理编码和路线计算。
- 地理编码仅组合小区、地址和楼栋，不发送姓名、单元、房号、电话、微信、门禁、钥匙或备注；成功坐标缓存到 Customer，并写入未执行 Task 地点快照。
- 客户小区、地址或楼栋变化会使 Customer 缓存失效；历史 Task 快照不批量覆盖，已有执行历史的单任务坐标不会被新地址改写。
- 日计划修订值纳入客户地图状态、任务坐标与预计到达字段；路线生成期间及采用时均再次保护并发变化。
- 当前路线严格按 P4 `sort_order`，推荐顺序只做简单稳定启发式，展示距离与时间仍由真实驾车路线 Provider 计算。
- `/admin/plans` 中栏升级为地图工作区，支持起点、可点击编号 Marker、真实折线、当前/推荐指标、未解析原因、失败提示和一键采用推荐。
- 前端建立可替换 `MapProvider`；有 JS API Key 时加载高德底图，未配置时使用真实坐标画布。相同客户的多次任务 Marker 做视觉展开但保持同一地理锚点。
- Marker 点击与右侧任务详情联动；已解析任务提供不含 Key 的高德导航链接，完整手机执行导航仍留给 P9。

## P6 完成内容

- 建立 `/api/admin/tasks/{task_id}` 单任务详情，以及开始、Checklist、执行文本、照片、完成与异常接口。
- 为每项 P6 写操作加入任务级 SHA-256 修订值，覆盖任务、订单、事项和照片状态；旧页面写入返回 `409`，不会产生部分更新。
