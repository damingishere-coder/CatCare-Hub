# 架构与数据一致性

## 运行边界

CatCare-Hub 采用单机、本地优先架构：React 管理端与移动端访问 FastAPI，本地业务数据写入 SQLite，现场照片写入本地文件系统。默认监听地址为 `127.0.0.1`，适合受信任电脑上的单人工作区。

客户填写采用不同的边界：公开构建只包含 `/fill/:token`，最小化 relay 将限定的 intake 请求写入专用中继数据库；本机 FastAPI 再通过受保护接口读取审核内容、执行本地归档并回写终态。仓库中的 CloudBase 目录是部署骨架，并不证明已有线上实例。

## 数据与文件

- 默认数据库：`data/catcare.db`。
- 数据库地址可由 `CATCARE_DATABASE_URL` 覆盖，测试和展示环境必须使用独立 SQLite。
- 照片保存到文件系统，数据库只保存元数据与关联关系。
- 不支持对非 SQLite 数据库自动执行迁移。

## 迁移与启动前检查

Alembic 是 schema 的唯一版本链。启动脚本会先检查数据库状态；SQLite 版本落后时先创建备份，再升级到迁移头。ready 检查同时确认 API 和数据库 schema 可用。

常用命令：

```powershell
migrate.bat
.venv\Scripts\python.exe -m alembic -c backend/alembic.ini current
.venv\Scripts\python.exe -m alembic -c backend/alembic.ini check
```

不要手工修改生产数据库的 Alembic version 表，也不要用测试数据库替换真实数据库。

## Revision 与并发覆盖保护

可变资源返回 revision。客户端更新时携带自己读取到的 revision；如果服务端版本已经变化，请求会失败并要求重新读取，而不是让较旧页面静默覆盖新内容。

这个机制用于保护并发编辑，但不是多用户权限系统。当前后台仍是本机免登录边界。

## 幂等与不可变原文

客户填写创建、提交与后台审核等关键动作使用 UUID 请求标识和幂等记录，避免网络重试重复生成客户、订单或审计事件。

客户提交后的原始 JSON 作为事实记录保持不可变。后台修改发生在 review draft；最终建档动作读取经过确认的草稿，同时保留原始输入与审核轨迹。

## 订单快照与审计

订单保存创建时的价格、客户、猫咪与照护快照，避免基础档案后续变更污染历史订单。付款作废、关键审核状态和资料归档使用追加式记录，支持追溯发生了什么。

## 路线规划与 Adapter

路线从家出发、访问当天任务并回到家。小规模任务使用精确搜索，任务较多时使用启发式顺序；地址过期、行政区不匹配或外部 Provider 不可用时，页面会显示状态并保留降级结果。

高德电动车路线与 AI 建议均为可选 Adapter：

- 未配置密钥时不发起外部请求。
- 请求失败或结果不合法时回退到本地能力。
- 外部建议必须经过服务者确认，不会自动修改真实订单或执行状态。

## 公开填写安全

relay 只允许约定的 intake 路径和字段，不转发管理 API。公开端不采集后台密码，不应采集钥匙具体位置或其他不必要的高风险信息。详细策略见[安全与私有访问](SECURITY_AND_PRIVATE_ACCESS.md)与[P22 设计记录](tasks/P22_WECHAT_CUSTOMER_INTAKE.md)。
